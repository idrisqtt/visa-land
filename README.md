# Visa Land

Адаптивный сайт авторских путешествий по Японии, Южной Корее и другим странам.

## Локальный запуск

```bash
python3 -m http.server 4173 --directory dist
```

После запуска откройте `http://localhost:4173`.

## Развёртывание на Vercel

Проект не требует установки зависимостей или сборки. Конфигурация в `vercel.json`
указывает Vercel публиковать содержимое каталога `dist`.

1. Импортируйте этот GitHub-репозиторий в Vercel.
2. Framework Preset: `Other`.
3. Build Command: оставить пустым.
4. Output Directory уже задан как `dist`.

## Страницы и редактор

- `/` — одностраничный сайт: `/#trips` — каталог с фильтрами, `/#calendar` — календарь, `/#visas` — визы, `/#about` — команда, `/#faq` — вопросы и ответы.
- `/trip.html?id=korea-japan` — отдельная страница программы; у каждого маршрута свой постоянный ID.
- Старые `/trips.html`, `/calendar.html`, `/visas.html`, `/about.html` (и адреса без `.html`) перенаправляют на соответствующие разделы главной, сохраняя якорь и параметры URL.
- `/admin/` — редактор, вход через существующий аккаунт Supabase Auth.

В редакторе «Туры» можно добавлять, копировать и удалять маршруты, менять порядок, публиковать или оставлять черновиками. Редактируются города, описание, цена, длительность, программа по дням, фотографии каждого дня, обложка, галерея, включённые и дополнительные услуги. Фотографии загружаются в существующий бакет `site-media` или задаются URL. Для нескольких фото выберите несколько файлов; порядок можно менять в списке URL.

Во вкладке «Календарь» добавляются независимые заезды: маршрут, начало/окончание, статус, места и публикация. Один маршрут может иметь любое число заездов. Сохранение обновляет каталог, программу и календарь одновременно. Несохранённые изменения и ошибки записи отображаются в редакторе.

## Данные и совместимость

### Первый экран

Hero использует `hero-desktop.mp4` на компьютерах и `hero-mobile.mp4` на телефонах (до 600px). Для каждого формата есть JPG-обложка из его видео. Старое значение `torii-loop.mp4` автоматически заменяется новой парой; загруженные через редактор пользовательские файлы сохраняют приоритет.

Вкладка `/admin/` → «Первый экран» управляет заголовком, описанием, подписью и кнопкой, режимом фото/видео, высотой секции, затемнением и точкой кадрирования отдельно для компьютера и телефона. Можно загрузить общий материал и отдельный вертикальный мобильный вариант. Если мобильный файл не задан, используется основной. Есть переключаемый предпросмотр двух форматов.

Видео: MP4 (предпочтительно H.264) или WebM, до 40 МБ с учётом ограничений существующего Storage; рекомендуем короткий ролик 10–20 секунд, 1920×1080 для компьютера и 1080×1920 для телефона. Фото/обложка: JPG, PNG или WebP до 5 МБ. Обложка остаётся видимой до начала воспроизведения, при отказе автозапуска, ошибке видео и reduced motion. Видео заполняет фон через `object-fit: cover`, сохраняет пропорции, воспроизводится без звука/inline, приостанавливается вне экрана.

Настройки хранятся в `site_config.content` (`heroMode`, `heroHeight`, `heroX/Y`, `heroMobileX/Y`, `heroShade`, `heroButton`, `heroButtonUrl`, `heroCaption`), файлы — в `site_config.media` (`heroPoster`, `heroVideo`, `heroMobilePoster`, `heroMobileVideo`). Существующие заголовок и описание используют прежние `heroTitle` и `heroCopy`.

Стек: статические HTML/CSS/JavaScript, Supabase Postgres + Auth + Storage. Production-зависимости и сборка не требуются. Запускайте сайт через HTTP-сервер; открытие `index.html` через `file://` не поддерживается.

Публичные страницы используют `catalog-data.js` (исходные маршруты), `catalog-model.js` (совместимость) и `pages.js` (вывод). Старые `app.js` и `site-bootstrap.js` сохранены для совместимости, но новые страницы их не подключают.

Существующая таблица `site_config` и её политики доступа используются без SQL-миграции. Туры хранятся в JSON-массиве `tours`; календарь — JSON-строкой `content.calendarData`, версия каталога — `content.catalogVersion = "2"`. После первого сохранения массив становится полным источником истины: удалённые туры не восстанавливаются из defaults. Старые данные дополняются исходной программой и сохраняются при первом редактировании. Пустой календарь и пустой каталог поддерживаются.

Доступ на запись должен оставаться ограниченным администраторами через существующие RLS-политики `site_config` и Storage. В браузере используется только публичный publishable key; сервисный ключ не требуется. Файлы при удалении маршрута физически не удаляются из Storage.

Анимации: переходы между страницами и фильтрами через View Transitions с обычной навигацией в браузерах без поддержки; раскрытие обложки маршрута; короткая обратная связь редактора. `prefers-reduced-motion` отключает пространственное движение; видео приостанавливается вне экрана и в скрытой вкладке.

Проверены синтаксис JavaScript, миграция старых данных, черновики и новые маршруты, независимые даты, сохранение полного payload редактора, удаление связанных заездов и сохранность черновика при ошибке записи. Запись в рабочий Supabase и загрузка реального файла не выполнялись без административной сессии; необходима финальная проверка сохранения под вашим аккаунтом.
