# Visa Land — UI/UX audit

Method: dual-agent (A: design_review · B: technical_scan)

## Design Health Score

Nielsen total: 24/40 — acceptable. The public site is cohesive and authored; the admin and high-stakes trip decision flow need substantial work.

## Design specificity

The public pages form a recognizable travel-editorial system through Manrope weight contrast, Porcelain/Matcha/Graphite/Tomato, documentary photography, square geometry, fine rules, and generous spacing. The admin is category-interchangeable: Forum, wine/beige gradients, glass panels, pills, large radii, and shadows conflict with the documented public system.

## What works

- Clear public information architecture: destinations, dates, organizer.
- Strong first-screen emotion and honest documentary imagery.
- Solid accessibility foundations: landmarks, skip links, current-page state, live result count, native details, reduced motion, and video pause behavior.

## Priority issues

1. P1: The admin edits many legacy fields no current public route consumes. Saving can report success without changing the visible site.
2. P1: The trip page does not answer high-stakes questions before WhatsApp: day descriptions, included/excluded services, organizer reassurance, payment/visa/cancellation context.
3. P1: Fallback calendar modeling may drop multiple departures for one tour and can show a card range instead of a departure date.
4. P1: Accessibility defects include placeholder-only admin login fields, suppressed focus outlines, low-contrast 9px admin labels, and tomato focus outlines on Matcha below 3:1.
5. P2: Bundled content waits behind a six-second remote request, and error recovery is distant and lacks retry.
6. P2: Mobile touch targets and content adaptation need hardening; several controls are below 44px and overflow is globally hidden.
7. P2: Shared asset cache versions differ between home v6 and other routes v5.

## Page notes

- Home: strongest surface; clear atmosphere-to-catalog-to-calendar path. Improve contextual proof and make fallback content immediate.
- Trips: comparison is simple and calm. Fix heading hierarchy and strengthen filters/touch targets.
- Trip: weakest conversion surface. Require a publish-ready content contract and bring confirmed trust information into the page.
- Calendar: ledger pattern is effective. Correct fallback entity modeling and add context-specific CTA.
- About/FAQ: strongest trust content. Reuse it contextually on trip pages.
- Admin: rebuild around actual route fields, route previews, explicit affected pages, clearer grouping, and the public design language.

## Persona red flags

- First-time buyer: understands the offer but cannot validate a roughly $3k decision on the trip page.
- Mobile Instagram visitor: faces remote loading delay, compact targets, and no mid-page contextual CTA on a long itinerary.
- Site operator: sees six tabs and many tour actions, but some saved fields have no visible public effect.

## Minor observations

- Header says “О нас и FAQ”, footer says “О проекте”.
- Selected departure prints raw ISO dates.
- `overflow-wrap:anywhere` may split Russian words poorly.
- Repeated identical CTA text misses route-specific intent.
- `body{overflow-x:hidden}` can mask real responsive defects.

## Questions

- Which should lead: public conversion path, admin reliability, or a full unified redesign?
- Should the admin adopt the public square editorial system or retain a deliberately separate softer back-office tone?
- Should implementation cover the top three P1 issues or the complete audit?
